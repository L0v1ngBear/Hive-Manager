# 售后多次处理

目标：同一工单追加多次补发配件/更换电机（可同时），独立物流、出库和回访，详情时间线和具体待办。质保始终沿用主工单开业日期，不重新起算。

非目标：订单重构、小程序、权限目录、部署包、既有工单数据重写。独立分支 codex/feat-aftersales-treatment-rounds，基线 9f8fb14。

兼容：原有处理/回访字段作为原记录保留；新增记录使用新表，不挪动既有配件和库存流水。旧接口保留；有新增处理时，工单结案增加未完成记录和最终回访校验。已结案工单通过显式追加处理继续服务，不覆盖旧处理或回访。取消工单不允许追加。

实现顺序见 todo.md。新增记录由主工单负责人处理（完整编辑权限可代处理），库存出库仍要求原出库权限；每次操作锁定主单并校验记录版本，避免重复出库和陈旧提交。新处理仅允许在原审批通过/不需审批、原配件已处理后追加，不能绕过既有审批。

验证：状态与结案策略单测 → 服务隔离、库存、质保和历史保护 → API契约 → 前端交互/待办 → 相邻售后/审批测试与构建。发布基线尚未对齐，不自动合并或覆盖桌面现有包。
