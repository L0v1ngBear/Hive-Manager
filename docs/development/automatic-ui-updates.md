# 网页自动更新

目标：部署新版本后，已加载本机制的管理页面自动使用新资源，无需退出登录。
范围：管理前端入口、构建版本文件、静态网页缓存策略；不修改业务接口、权限、订单数据或登录存储。

- 每次生产构建生成唯一版本号，同时写入 JS、HTML 元信息和 `dist/version.json`；文件自动进入前端产物清单。
- 页面启动、每30秒、窗口获得焦点、切回可见状态，以及资源预加载出错时检查版本。
- 版本检查绕过浏览器缓存；只有版本文件和入口HTML版本一致时才提示更新。
- 提示10秒后自动刷新，保留路径、查询参数、锚点和 sessionStorage 登录凭据。未保存编辑可能丢失，因此提示用户及时保存。
- 每个目标版本每个标签页最多自动跳转一次；使用版本查询参数和会话记录共同防止刷新循环。断网、无效响应及上传中的版本不一致不触发刷新。
- Nginx 网页入口禁止缓存；带内容哈希的 assets 保留长期缓存；入口原有安全响应头保持不变。API代理不变。
- 首次上线时，已经打开且没有本机制的旧页面必须刷新一次；服务器无法让尚未运行检测代码的旧页面自动执行此功能。后续发布自动检测。

验证：版本一致/变化、断网、半发布、重复检测、受限存储、可见性事件、构建标识一致性、缓存配置测试；两个真实构建版本和真实后端的浏览器切换验证自动刷新与登录保留。生产Nginx运行检查仍由服务器发布流程执行。
