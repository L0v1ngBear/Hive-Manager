# 网页发布推送与静默更新

目标：部署新版本后，已加载本机制的管理页面自动使用新资源，无需退出登录。
范围：管理前端入口、构建版本文件、只读版本事件接口及对应部署代理；不修改既有业务接口、权限、订单数据或登录存储。

- 每次生产构建生成唯一版本号，同时写入 JS、HTML 元信息和 `dist/version.json`；文件自动进入前端产物清单。
- 页面仅建立 `/api/release/events` SSE 长连接，没有定时版本轮询、切回页面检查、提示或倒计时。
- 后端启动时读取只读挂载的 `version.json`，在服务就绪后向连接发送当前构建标识。正常 `bash publish.sh` 会重启后端，旧页面的事件连接自动重连并收到新版标识。业务数据和账号凭据不进入公开事件接口。
- 同版本事件直接忽略；仅收到新版本事件时无缓存获取一次入口HTML，核对与推送的版本一致后立即静默刷新。
- 保留路径、查询参数、锚点和 sessionStorage 登录凭据；按用户要求不提示，未保存编辑可能丢失。
- 每个目标版本每个标签页最多自动跳转一次；使用版本查询参数和会话记录共同防止刷新循环。断网、无效响应及上传中的版本不一致不触发刷新。
- SSE每25秒发送保活注释，用于维持代理连接和清理断开客户端；保活不查询版本，也不会引起页面请求或刷新。连接断开由浏览器按服务端给出的15秒间隔重连。
- Nginx 网页入口禁止缓存；带内容哈希的 assets 保留长期缓存；入口原有安全响应头保持不变。API代理不变。
- 首次上线时，已经打开且没有本机制的旧页面必须刷新一次；服务器无法让尚未运行检测代码的旧页面自动执行此功能。后续发布自动检测。

验证：同版本静默、事件触发立即刷新、断网和半发布防误刷新、重复事件防循环、构建标识一致性、缓存及部署配置契约；后端验证就绪事件与重连、配置文件校验及无配置开发兼容。真实浏览器保持页面超过30秒、实际重启Java后端，验证无版本轮询、SSE重连、静默刷新和登录保留。生产Nginx运行检查仍由服务器发布流程执行。
