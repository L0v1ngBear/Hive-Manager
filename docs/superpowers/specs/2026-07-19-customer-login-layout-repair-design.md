# 客户管理与登录页排版修复设计

日期：2026-07-19

## 目标

本次调整解决管理端客户管理页面在常见电脑宽度下的排版错乱，并将登录页调整为用户确认的“标准企业双栏”结构。客户业务逻辑、登录能力、现有品牌和文字信息均保持不变。

## 问题与根因

### 客户管理页面

客户管理页面把 `v-filter-collapse` 直接挂在 `function-page-header` 内的筛选网格上。该指令会在筛选网格前动态插入一个 `.function-filter-collapse-bar`。这个工具条具有 `width: 100%` 和 `flex: 1 0 100%`，而页面头部在 768px 以上切换为不换行的横向 Flex 布局，因此标题、满宽工具条和多列筛选控件会争夺同一行宽度并产生挤压或溢出。

页面还只有一个“客户总数”卡片，却使用共享的四列统计网格，使摘要区在部分宽度下形成不自然的空列和尺寸跳变。

### 登录页面

现有页面同时使用大幅背景装饰、顶部品牌标题、二维码区域和账号表单，视觉焦点分散。用户已在可视化对比中确认采用“标准企业双栏”方案。

## 客户管理页面设计

页面按标准列表页拆分为四个稳定区块：

1. 标题区：左侧保留“客户经营中心”、标题和说明，右侧只保留“新建客户”主按钮。
2. 摘要区：使用独立的单列客户摘要样式，显示客户总数，不再套用四列统计布局。
3. 列表工具区：把折叠筛选工具条和筛选表单移入列表面板顶部，二者处于同一纵向容器。
4. 数据区：筛选区下方依次放置可横向滚动的客户表格和分页栏；操作列固定在右侧，避免横向滚动后丢失操作入口。

筛选响应式规则：

- 宽屏：关键词占较宽列，其余条件按可用空间排列。
- 平板：筛选控件按两列排列。
- 手机：筛选控件、操作按钮和新建按钮均按单列或满宽排列。

折叠筛选功能继续保留，但不再向横向标题区插入满宽节点。

## 登录页面设计

采用用户选择的“标准企业双栏”：

- 页面中央保留一个主要登录容器。
- 左栏承载现有品牌、产品介绍和辅助说明，形成稳定的品牌区。
- 右栏承载登录操作，并提供“账号登录 / 扫码登录”两个标签。
- 默认展示账号登录；切换到扫码登录后展示现有二维码、扫码状态、过期刷新和确认成功状态。
- “首次登录 / 忘记密码”“记住账号”“使用组织码加入组织”继续保留。
- 密码重置弹窗、扫码轮询、登录跳转和错误提示逻辑不改变。
- 现有页面文字、Logo、产品名称、隐私政策、服务条款和备案信息不替换。

响应式规则：

- 桌面端使用左右双栏。
- 窄屏下改为单列，品牌区压缩为顶部介绍区，登录操作区在下方完整显示。
- 登录表单和二维码均不得超出视口宽度，移动端不产生横向滚动。

## 代码边界

计划修改：

- `management-ui/src/views/function/customer/customer.vue`
- `management-ui/src/views/Login.vue`
- 必要时在上述组件的 scoped style 或现有共享样式中增加页面专用规则
- 对应管理端测试文件

不修改：

- 后端接口及数据库
- 客户筛选、分页、详情、编辑和权限逻辑
- 登录 API、账号认证、扫码会话和密码重置业务逻辑
- 登录页现有信息和全局租户品牌规则

## 测试与验收

自动化测试采用测试驱动方式：

1. 先增加客户页结构回归测试，证明筛选折叠节点不再位于横向标题区，并要求操作列固定。
2. 先增加登录页结构回归测试，要求双栏容器、登录方式切换和移动端单列规则存在，同时确认现有登录入口仍保留。
3. 运行客户、登录和全局响应式相关测试。
4. 运行管理端完整测试和正式构建。

视觉验收覆盖：

- 1440px 桌面宽度
- 1024px 笔记本/平板横屏宽度
- 390px 手机宽度

验收标准：页面无横向溢出、控件不重叠、折叠筛选可用、表格操作入口可见、登录两种方式可切换，原有业务行为不回退。
